## Column meanings

- **MCP version:** the server version (`mcp-frappe --version`) or commit the task used; `unknown` when it was not recorded.
- **Tool outcome:** whether MCP calls returned the expected result. Use `partial` if some calls failed or were blocked.
- **Task outcome:** whether the intended result was independently verified. Use `partial` or `unverified` when task-level behavior was not fully checked.
- **Blocked by MCP:** `no`, or the FR or BUG id when a missing operation or an MCP defect stopped part of the task. A site that was down, a permission denial, or a documented safety refusal is `no`.
- A permission denial or documented safety refusal is not an MCP defect. File a bug only for an unexpected tool failure or incorrect result.

## Reporting rules

Log one row for every task that invokes Frappe MCP. Write a separate sanitized task report in [reports/](reports/) only when the task made a write, hit a failure, or found a gap, and its details can be shared in this repository; the report gives its objective, connection alias, exact MCP tools and purpose, per-operation outcome, safe evidence, errors, and pending work. Keep reports containing private project details in the consuming repository and use `none; detailed report is kept in the consuming repository` in this log. Otherwise the row is the whole record, and its evidence cell says `none; no write, failure, or gap`. If an operation is missing, add or update a feature request; if a tool has a reproducible defect, add or update a bug report. Link shareable reports and feedback items in the row.

Never include raw tool output, credentials, private site URLs, user identities, customer or business data, private tracker links, or internal deployment identifiers. Use a safe artifact link or write `none`.
