# Security Policy

## Supported versions

Security fixes are intended for the current maintained release. Until releases are published, report the affected commit or checkout version when contacting maintainers.

## Reporting a vulnerability

Do not report suspected vulnerabilities in a public issue. Use GitHub's private vulnerability reporting feature if enabled for this repository. If it is unavailable, contact the repository maintainers privately using the contact published on the repository page.

Include a concise impact description, affected versions/commit, reproduction steps, and any relevant sanitized logs. Do not include API keys, customer data, production files, or personal data. Rotate any credential that may have been exposed.

The project has no published security contact until its public repository is established; repository owners should enable private vulnerability reporting and add a monitored security contact before announcing the project.
